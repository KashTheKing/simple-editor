# Simple Editor — UI/UX overhaul plan

_Generated 2026-09-04 from a 3-phase multi-agent workflow (codebase + competitor analysis → 4-way design panel → verified per-workstream plans). Source research JSON lives in the session scratchpad; this file is the authoritative plan. Each workstream is also a GitHub issue (#16–#38, label `ui-overhaul`, `wave-N`); implement one with `/se-implement <issue number>` or `/se-implement plans/ui-overhaul/issues/<name>.md`._

## Thesis

Simple Editor already owns the engine the four competitors sell (MF/ffmpeg decode, proxies, read-ahead cache, GPU effect pipeline, nodes, tracking, whisper, MCP+Luau). The overhaul adds the missing editing grammar and beginner surface as thin verbs over ~8 primitives (per-track {locked, ripple, magnetic} + shift_time + O(n) per-track gap ops; tiered snap_target with a guide line; Clock.rate/loop + an async request_layers render channel; a Peaks analysis module; a persisted transcript + cut_word_ranges; frame_stats readback; a thumbnail-catalogue generaliser; Toast/Confirm/autosave forgiveness plumbing) and makes every verb four bindings of one function: model op → ToolDef row → Action/hotkey → palette. Concurrency is structural: wave 0 is three serial, individually reviewable PRs (pure moves → registries + schema-first serde fields + pre-placed no-op hooks → size-diet + deletions) that turn app.rs/model.rs/timeline.rs into child modules with five const registries (TOOL_TABLES, ACT_HANDLERS, FRAME_HOOKS, WINDOW_DRAWERS, PANE_DRAWERS) pre-seeded with one marker section per workstream, so 23 workstreams in waves of ≤8 worktrees add files and fill their own section, never another owner's lines. MCP/Luau parity is a build failure, not a review item: every_edit_op_has_a_tool scans model ops, ui.action covers every Action, mutate rows roll back on error, and the same table feeds tools/list, editor.tools() and the palette; Luau gains -- @on event hooks. Size trends down first: 15.73 MB → ≈10.4 MB after wave 0 (commonmark −2.0, embedded fonts −1.41, persistence −0.25, deps at -Os −0.7, gated main-crate -Os −0.98, dedupe −0.1), then ~23k feature lines at one measured density (0.08 KB/line) land ≈12.2 MB upper bound (≈11.8 with -Os), every PR gated by scripts/size.ps1 + size_log.csv. Beginners get Simple layout + Dynamic mode, magnetic V1/A1 with position-locked secondaries, Undo toasts instead of dialogs, Gallery (re-purposed Presets pane), Quick Export tiles and autosave; pros get the Avid/Premiere/Resolve chord table verbatim (J/K/L, U [ ] Q W E ; ' / A Ctrl+D Ctrl+F Ctrl+M), non-modal trims on one decided modifier table (pure arm() fn, tested per row), a dockable Pane::Source two-up, trim view + dynamic trim, scopes, LUTs/Primaries/Qualifier, beats/ducking/LUFS, multicam — all one editor.tool() call away.

## Principles

- Delete before you add: wave 0c lands the whole dependency diet and every verified dead/duplicate path before any feature PR; scripts/size.ps1 + size_log.csv make each PR's delta visible and /se-verify fails > +64 KB without a `size:` line.
- One primitive, many verbs: no UI gesture, hotkey or palette row ships without a `Project::` fn with a unit test and a ToolDef row; every_edit_op_has_a_tool / ui_action_covers_every_action fail the build otherwise.
- Registries are files, not match arms: a workstream adds `tools_<ws>.rs` / `<ws>_ctl.rs` and fills its own pre-seeded `// ---- ws:<name> ----` section in TOOL_TABLES/ACT_HANDLERS/FRAME_HOOKS/WINDOW_DRAWERS/PANE_DRAWERS, actions!, Glyph lists, Settings/Project/App structs; nobody edits another section.
- Schema first: every new serde field lands in wave 0b with #[serde(default)] (Track.ripple as Option<bool> resolved in from_json), Project::VERSION = 2 warns on newer files; feature branches never touch a type definition.
- Beginner-safe default, pro behaviour one modifier/flag/keystroke away: plain drag = no-overlap move, plain edge = plain trim, Delete non-ripple; V1/A1 ripple=true and later tracks position-locked; magnetic (gapless) is a per-track opt-in; every detection offers Mark-instead / dry_run first and leaves editable clips/keyframes/markers.
- Non-modal forever: no new Tool buttons (Tool::Zoom deleted, no Tool::Crop); trims are cursor zones + the one modifier table in `arm()`; Alt-drag gestures arm only after egui's drag threshold so Alt+click single-select survives.
- Zero new panes unless dockable matters: overlays (palette, onboarding, trim view, scopes window, angle grid, overview strip), collapsible sections (transcript, Color) and the re-purposed Presets→Gallery pane; Pane::Source is the one new variant, pre-declared in wave 0b, tab-stacked hidden in Simple, never in ROUND3.
- Popups never block: 14 rfd Yes/No sites become confirm::ask() (egui::Window) or an undoable op + Undo toast; Settings-level destruction snapshots Settings for an Undo toast; no egui::Modal, nothing synchronous on the first frame.
- Idle CPU stays 0%: App::animate_until(Instant) is the only timed-repaint path; every new pane/overlay test calls assert_no_idle_repaint; --selftest has an idle step; alt renders pause while an export is serviced.
- Playback-cache invariants are load-bearing: ops mutate clips in place (stable ids, same track index, Transition.id kept); track flags/colour/volume never enter video_dirty_spans' full-clear list (test pins it); Track.id reorder forces a full clear; ripple/segment drags ghost-paint and apply on release.
- Alt renders are async and GPU-accurate: hover preview, trim view, scopes, wipe and angle grid consume Player::request_layers + the UI-thread GPU renderer, never the blocking CPU render_once.
- Undo once per gesture, before mutating, only if changed; every new Action uses push_undo_labeled so History reads 'Ripple trim', not 'Project edited'.
- Mark every deliberate ceiling `// ponytail: <what> — <upgrade path>`; zero new crates, egui 0.33/egui_tiles 0.14 pinned, no neural inference, no network at startup.

## Decisions (resolved open questions and judge findings)

- **Size arithmetic (fatal flaw)** — One density for everything: 0.08 KB per new source line (measured 15.73 MB − ~10.8 MB deps ≈ 4.9 MB over 67.9k lines = 13.8 lines/KB, rounded to 12.5 as an upper bound). Diet booked from measured facts only: commonmark −2000 (12.97→15.06 when added), fonts −1410 (TTF on disk), persistence −250, deps -Os −700, dedupe −100; Luau ~2 MB fixed (luau0-src lib.rs:135 opt_level(2)). Projection per wave in size_plan; upper bound ≈12.2 MB after wave 3, ≈11.8 with the -Os discount on new code.  
  _Why:_ The winner's prose (~11 MB) and table (≈15.3 MB) used two coefficients; judges asked for one and a per-wave figure.
- **Wave shape / concurrency (fatal flaw)** — 4 waves: 0 = three serial PRs (0a moves, 0b registries+schema+hooks, 0c size-diet+deletions); 1 = 8 concurrent; 2 = 8 concurrent; 3 = 4. timeline.rs is split into mod/snap/arm/cue_lane/gestures/header/paint/menus so the per-wave exclusive owner of timeline/mod.rs (snap-engine → trim-gestures → pro-timeline) edits a ~700-line hub, not 4.3k lines.  
  _Why:_ Judges: six-wide waves under-deliver on 'several worktrees'; ≤8 fits 4–8 agents; a 20k-line wave-0 mega-PR is unreviewable.
- **Registry merge conflicts (fatal flaw)** — Per-workstream marker sections pre-seeded in wave 0b in every shared table (registries, mod lists, actions!, Glyph lists, Settings/Project/App structs + Default/new literals); .gitattributes merge=union only for size_log.csv and CHANGELOG.md (append-only text). Rust sources rely on disjoint hunks + compiler/tests, never union.  
  _Why:_ END-append conflicts on every landing; union on Rust code can silently duplicate rows.
- **Tier-2 rfd/cpal rewrites and 'lite' exe (fatal flaw)** — Rejected. rfd→IFileDialog and cpal→WASAPI rewrites are not scheduled; `lite` feature set stays a documented escape hatch (docs-refresh) and is never the shipped artifact.  
  _Why:_ ~0.6 MB for two rewrites of working code contradicts delete-before-add; a second exe dodges the single-binary goal.
- **Default keymap (fatal flaw / open question)** — Pro design's chord table adopted verbatim where it verifies free (see keymap); changes: ±10-frame trims on Ctrl+[ / Ctrl+] (Shift+[ reaches egui as logical `{` and egui 0.33 consume_key has no physical-key fallback), layout-mode toggle on Ctrl+Shift+G (Shift+Tab = egui focus, Ctrl+Shift+Tab avoided), Alt+Space rejected (Windows system menu), F1 = cheat sheet (second palette entry point). Existing defaults are never re-keyed; Premiere/Resolve/Avid presets are diff tables validated by a test.  
  _Why:_ Keyboard-first grammar must be decided at design time; every chord checked against hotkeys.rs and the out-of-table consumers (bare S, Shift+S, Ctrl+Y, Backspace, Esc, Tab).
- **Modifier table (open question)** — Frozen as `arm(mods, zone, track_flags, tool) -> Option<GestureKind>` in src/ui/timeline/arm.rs (wave 1 snap-engine) with one test per (zone, modifier) row; gestures.rs (wave 2) only consumes it. Plain edge = Trim, Ctrl+edge = RippleTrim, Alt+edge = Roll, Shift+edge = RateStretch, Alt+body drag = Slip (after drag threshold), Ctrl+Alt+body = Slide, Ctrl+Shift+body = Segment, drops Ctrl/Alt/Shift = Splice/Overwrite/PlaceOnTop; Delete non-ripple; Track.magnetic=true flips plain edge→ripple and Delete→close gap on that track only.  
  _Why:_ Ctrl/Alt/Shift at press are already selection modifiers (timeline.rs:2306-2330); Ctrl+body is kept for additive select+move, so Segment takes Ctrl+Shift.
- **Hold-Alt snap override (open question, row 21)** — Skipped: bare S (tools.rs:567) already toggles snapping mid-drag and the new guide line shows the state; Alt is spoken for (single-select, slip, roll).  
  _Why:_ Zero code, no modifier collision.
- **New panes (open question)** — Exactly one: Pane::Source (dockable two-up), declared in wave 0b in Pane::ALL (now a slice), glyph/title, every preset via stack_unplaced, tab-stacked behind Library in Simple, not ROUND3. Color = inspector section + Gallery LUT/Looks tabs; Scopes = egui::Window; Transcript = collapsible section in Subtitles; Titles/Captions = Gallery tabs; Overview = inline minimap strip above the ruler; Trim view/wipe = Preview overlay; Multicam angle grid = egui::Window; Pane::Presets variant kept, drawer = Gallery.  
  _Why:_ Each Pane costs preset builders, icon key, toggle Action, tests and View-menu clutter; stored layouts stay valid.
- **Main-crate opt-level 's' (open question)** — Landed in 0c as the last measured step behind gates: bench_4k_preview ≤ +10 %, headless_1000_clips_stays_fast < 10 ms, selftest export time ≤ +10 %. Fail → revert that line, keep deps at -Os, and a follow-up `se-engine` workspace member (compose/mixer/mixer_fx/effects/gpu/shaders at -O3) is the documented upgrade path (not scheduled).  
  _Why:_ Hot paths are GPU shaders, MF decode and block DSP; the gate makes the gamble measurable.
- **Pane::Presets fate (open question)** — Keep the variant; presets_ui.rs deleted in 0c and the drawer paints library reuse rows until wave-2 inspector-gallery turns it into the Gallery.  
  _Why:_ Removing the variant resets every stored layout.
- **eframe persistence (open question)** — Dropped in 0c; window rect via winpos.rs in Settings; inspector fold state in Settings.inspector_folds (wave 2).  
  _Why:_ −0.25 MB; the only user-visible state it held moves to Settings.
- **Autosave cadence and .sedit.lock (open question)** — Settings.autosave_secs (default 30, 0 = off) exposed in General; autosave to %LOCALAPPDATA%\SimpleEditor\autosave, 20 rolling copies, off-thread, skipped while untitled/exporting over the source. `.sedit.lock` is warn-only (toast) including when MCP co-editing is on.  
  _Why:_ Roaming %APPDATA% is wrong for multi-MB copies; refusing a second writer would block the co-editing flow.
- **Multicam scope (open question)** — Minimal in wave 3 pro-monitor: create from xcorr offsets → nested sequence with one track per angle, switch = split + enabled toggles, angle grid as an egui::Window capped at 4 angles at ¼ size via request_layers.  
  _Why:_ Editable, no new pane, bounded render load.
- **Track reorder (open question)** — Allowed (wave 3 pro-timeline); video_dirty_spans returns None when a Track.id differs at any index (landed wave 1 player-rate-loop with a flags_do_not_dirty_video test).  
  _Why:_ Same-kind reorder serves stale z-order today.
- **Alt-render contention during export (open question)** — Pause hover/trim/scopes/angle renders while self.export.is_some(); otherwise one request in flight per consumer, newest wins.  
  _Why:_ The UI thread also serves GpuFrameRequests during export.
- **Lite feature set (open question)** — Documented only (docs-refresh): which modules a `--no-default-features --features lite` build would drop (scripting, tracking, planner, color, titles, multicam) and the expected ≈9.5 MB; no CI build, no cfg gates added.  
  _Why:_ Escape hatch, not a shipped variant.
- **Pop-out hotkeys** — 0b pre-places `on_viewport: &mut dyn FnMut(&egui::Context)` in layout::show, called inside show_viewport_immediate; wave-2 layout-modes fills it with hotkeys.poll on the child ctx feeding pending_actions (consumed once per viewport).  
  _Why:_ Hotkeys are polled on the root ctx only today (app.rs:6266); Space/JKL are inert in a popped Preview.
- **Command type change** — Action stays the hotkey unit (no Vec<Command> change to Hotkeys::poll); palette rows wrap Action \| Pane \| Tool \| Script \| Workspace in a Command enum local to palette.rs.  
  _Why:_ A mid-wave type change forces every concurrent branch to rebase (custom design's fatal flaw).

## Shared-registry protocol (how concurrent worktrees merge cleanly)

Wave 0b creates every extension point with one pre-seeded, named section per workstream (23 sections, ordered by wave then name); a workstream edits ONLY inside its own section, so hunks never overlap. (1) src/ui/app/mod.rs: `TOOL_TABLES: &[&[ToolDef]]`, `ACT_HANDLERS: &[fn(&mut App, Action) -> bool]`, `FRAME_HOOKS`/`WINDOW_DRAWERS: &[fn(&mut App, &egui::Context)]`, `PANE_DRAWERS: &[fn(&mut App, &mut egui::Ui, Pane) -> bool]` and the `mod` list — each literal holds 23 `// ---- ws:<name> ----` comment lines; a workstream replaces its own line with `tools_<ws>::TOOLS,` / `<ws>_ctl::act,` etc. act()/update()/windows()/draw_pane_inner fall through to the registries (first `true` wins; PANE_DRAWERS before the legacy match). (2) src/hotkeys.rs actions!: 23 section comments before the tool block; rows go inside the owner's section; no_duplicate_defaults + reserved_chords_are_free (bare S, Shift+S, Ctrl+Y, Backspace, Esc, Tab/Shift+Tab, Alt+Space) guard. (3) src/ui/tools.rs Glyph enum/ALL/name/from_name/draw_glyph carry the sections; every_glyph_paints_a_picture guards. (4) Settings (+Default), Project (+Default), App (+new literal), Track/Clip/Asset/Cue/TextStyle carry sections, but 0b already lands every planned serde field, so features add Settings fields only. (5) Pane::ALL is a slice with sections; preset builders end in `stack_unplaced(tree, placed)`; ROUND3 frozen. (6) Files: disjoint owns_files per workstream; files passing between waves (timeline/mod.rs, preview.rs, menus.rs, settings_ui/*, files.rs, boot.rs, library.rs, subtitles_ui.rs, gallery.rs) have exactly one exclusive owner per wave named in touches_shared, never co-owned inside a wave. (7) Cross-workstream call sites are 0b no-op hooks (autosave_tick, playback_tick, auto_surface, help_extra, workspace_strip, on_viewport, fire_hook, cue_layer_at, master_effects prepend, place_asset(DropMode), asset_status, alt_render field, EffectsResponse/TransitionsResponse.hover, Mixer track-volume sampling) so owners fill their own file. (8) .gitattributes: `size_log.csv merge=union`, `CHANGELOG.md merge=union`; Rust files never use union. (9) Landing: rebase, `cargo test` (structural tests catch a bad section), `scripts/size.ps1 -Note <ws>`, PR body `size: ±N KB` + ws name; agents.md records these rules and se-review checks that a PR adding an Action row, Gesture variant, Pane or `pub fn …(&mut self` on Project also adds a ToolDef row.

## MCP / Luau parity (every feature has AI tooling)

Wave 0b replaces the three hand-kept lists (mcp/tools.rs 64-row tuple TOOLS, the run_tool match ending app.rs:5741, MUTATING_TOOLS app.rs:881) with `ToolDef { name, desc, args: &["name:type:required:desc"], kind: ToolKind, run: fn(&mut App, &Value) -> Result<ToolOutcome, String> }`, `enum ToolKind { Read, Mutate, Job, Ui }`, `enum ToolOutcome { Done(Value), Job(Arc<Progress>, PathBuf) }`. Each owner file declares `pub const TOOLS: &[ToolDef]` beside its free fns (child modules of ui::app see App's private fields, so the 64 arm bodies move verbatim) and registers one line in TOOL_TABLES. `mcp::tools::{all, find, list_json, input_schema}` flatten TOOL_TABLES for tools/list, Luau's editor.tools() (gains arg docs) and the palette (arg-free tools become rows; `:` mode builds a mini arg form from the docs). `App::run_tool_undoable(name, args)` is the single wrapper for MCP, scripts and palette: Mutate → snapshot JSON, run, push_undo_labeled(name) iff JSON changed, after_edit, rollback on Err; Read/Ui → run; Job → existing McpJob poll (ToolKind::Job replaces the name-matched 30-min timeout at mcp/mod.rs:342). Arg-free UI verbs need no bespoke tool: `ui.action(id)` resolves Action::from_id, checks `App::enabled(a) -> Result<(), &'static str>` (Err text = toast reason) and pushes pending_actions; `ui.actions`, `selection.get/set`, `playhead.get` complete the bridge (all in 0b). Luau: `editor.tool` unchanged; scripts gain `-- @name/@desc/@icon/@hotkey/@on <event>/@budget_ms` headers (command-palette ws) and `App::fire_hook(event, payload)` (0b stub, wave-1 real) runs `@on` scripts for selection_changed, import, export_done, project_open, project_save, marker_added with a 250 ms budget and disable-on-overrun toast; `settings.set` over MCP is whitelisted to scalar keys. Process rule (agents.md + se-review): a PR adding an Action row, Gesture variant, Pane or Project mutator adds a ToolDef in its own tools_<ws>.rs; the structural tests make the omission a build failure.

**Argument defaults:** `Args<'a>(&'a Value)` helper in src/ui/app/tools_args.rs (0b): typed getters f64/id/ids/str/bool, `ids_or_selection(key, app)` (omitted clip_ids → current selection, else expand_links of the clip under the playhead), `t_or_playhead(key, app)`, `track_or_hovered(key, app)`; every detection tool accepts `dry_run:boolean` / `as_markers:boolean` (Mark instead) defaulting to false; times in seconds, ids u64, mutating tools return {ok:true,…}.
