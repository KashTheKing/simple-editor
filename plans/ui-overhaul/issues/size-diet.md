# size-diet

**Workstream:** `size-diet` · **Issue:** [#18](https://github.com/KashTheKing/simple-editor/issues/18) · **Wave:** 0 · **Branch/worktree:** `chore/size-diet` → `../simple-editor-wt/size-diet` · **Depends on:** registries-schema-hooks · **~350 new lines · Δ exe ≈ -5410 KB**

Read [agents.md](../../../agents.md), [goals.md](../../../goals.md), [notes.md](../../../notes.md) and the master plan [README.md](../README.md) (registry protocol, keymap, modifier table) before starting.

## Summary

"Pays down the size debt before any feature workstream lands: measured baseline is 15.73 MB (15,732,736 B, sha 6b92982), not goals.md's stale 12.97 MB. Deletes egui_commonmark/_backend/egui_extras/pulldown-cmark (~2000 KB, replaced by a 250-line ui::markdown.rs used by planner Notes and a new What's New window), eframe's embedded default_fonts (1,407,752 B of Ubuntu/Hack/NotoEmoji, verified byte-exact against epaint_default_fonts-0.33.3's four TTFs — replaced by Segoe UI/Consolas read from %WINDIR%\\Fonts, already the pattern theme.rs uses today for Segoe UI alone), and eframe's persistence feature (~250 KB; window rect moves into Settings via winpos.rs, its debounce routed through App::animate_until — the sanctioned repaint helper for code this PR adds). Adds dependency-wide opt-level \"s\" (~700 KB) and, gated on bench_4k_preview/1000-clip/export-time, main-crate opt-level \"s\" (~980 KB, revert on regression). Deletes genuinely dead code found by direct inspection: Tool::Zoom (an unbound, always-no-op tool across timeline.rs/preview.rs, including its tool_drag guard at preview.rs:507 — grep-confirmed the only other reference to the variant crate-wide), presets_ui.rs (270 lines; Pane::Presets repoints to library::reuse_ui per the architecture's own interim decision), library.rs's sequences_section/templates_section (zero or test-only call sites), and app.rs's duplicated scrub-bar painting (folded into preview::scrub_bar). Lands scripts/size.ps1 + size_log.csv + a size ceiling in /se-verify, plus a headless idle-repaint step in --selftest — the two structural gates goals.md has been asking for without automation. One capability this PR deletes (saving a new preset from selection) gets one new MCP tool (templates.save) so it stays reachable via scripting/palette even without its old UI. Audit correction: grep confirms 17 pre-existing raw request_repaint_after calls already exist in app.rs/planner.rs/preview.rs/subtitles_ui.rs with no prior animate_until fn — this plan now states plainly that animate_until governs only the NEW repaint code this PR adds, not those 17 sites, and defers their migration (files owned by other workstreams) rather than silently implying the invariant already holds. notes.md is deliberately left untouched — it is docs-refresh's (wave 3) exclusive file and not in the merge=union list."

## Motivation

"goals.md's #1 core goal (\"Target ~10 MB release exe\") has been drifting the wrong way: 12.97 MB (stale reading) -> measured 15.73 MB after egui_commonmark landed, per the architecture's own size_plan. Two of the three critique_missing_hooks this workstream closes are explicit: 'binary-size and idle-CPU gates in /se-verify' (no automated ceiling exists today; agents.md only asks for a manual check) and the \"What's new\"/version-gate hook (env!(CARGO_PKG_VERSION) is currently read but never compared to anything). This is also wave 0's only large NEGATIVE size delta — landing it before any of the 20 feature workstreams start is what makes their combined ~23k new lines land at ~12.2 MB instead of ~18 MB. Audit follow-up: the codebase already has 17 raw request_repaint_after call sites and no animate_until helper exists yet anywhere, so this PR's own claims are now scoped precisely to the NEW call sites it adds (winpos.rs, whatsnew.rs) rather than implying a codebase-wide invariant that isn't true on day one."

## In scope

- Drop egui_commonmark/_backend/egui_extras/pulldown-cmark; ship ui/markdown.rs for planner Notes + the new What's New window.
- Drop eframe default_fonts; load Segoe UI + Consolas (with a fallback chain) from %WINDIR%\Fonts.
- Drop eframe persistence; move the window rect into Settings via winpos.rs (debounced save routed through App::animate_until for this PR's own new code, seeded at launch).
- Dependency-wide opt-level "s"; main-crate opt-level "s" gated on perf benches (revert on failure).
- Delete Tool::Zoom (always-no-op) end to end, including its tool_drag guard reference in preview.rs:507; delete presets_ui.rs, sequences_section, templates_section (verified dead/superseded); dedupe the lib-preview scrub bar into preview::scrub_bar.
- scripts/size.ps1 + size_log.csv + a size ceiling in /se-verify; a headless idle-repaint step in --selftest.
- One new MCP tool (help.changelog) for the version gate, plus templates.save to keep the deleted Save-from-selection capability reachable.
- Correct the architecture's animate_until wording (CHANGELOG.md, goals.md, this plan's own acceptance criteria/ponytail_notes) to scope it to new code, since 17 pre-existing raw repaint-timer sites are verified still present and are not migrated here.

## Out of scope

- Settings.show_library/show_inspector deletion and the inspector Asset block -> 'Show in Library' link collapse: the god_file_split table's wave-0c bundle names these, but they live in settings.rs (struct-shape) and inspector.rs, both owned by registries-schema-hooks in wave 0b, not listed in size-diet's own files list — left as a follow-up rather than risking a cross-file collision.
- The general-purpose assert_no_idle_repaint(ui closure) harness helper 'every new pane/overlay test must call' — not owned here; assumed to already exist (or be added) by registries-schema-hooks, which this workstream depends on.
- Rebuilding Pane::Presets into the Gallery pane (speed-ramp/LUT/caption/template browsing) — that is wave-2 inspector-gallery's job.
- ARCHITECTURE.md's module map / the docs pass generally — owned by split-god-files (module map) and docs-refresh (wave 3); notes.md is deliberately NOT touched by this workstream (see ponytail_notes / changelog) since it is docs-refresh's exclusive file and not merge=union.
- A `lite` feature-set build, rfd/cpal rewrites, or any new dependency — explicitly rejected by the architecture.
- Migrating the 17 pre-existing raw request_repaint_after call sites (app.rs, planner.rs, preview.rs, subtitles_ui.rs) to animate_until — most sit in files another workstream owns exclusively in a later wave; a follow-up `chore/migrate-repaint-timers` (unscheduled) is the documented path, ideally folded into each file's next feature PR rather than a standalone cross-cutting sweep.

|---|---|
| egui panics if a FontFamily has zero fonts once default_fonts is dropped (a Windows SKU missing Segoe UI/Consolas). | Ordered fallback chain per family (segoeui->tahoma->arial; consola->cour->lucon) plus a last-resort fontdb::Database::load_system_fonts() scan; the candidate-list logic gets a unit test with a temp dir missing every named file. |
| Dropping eframe's `persistence` feature also drops egui's own CollapsingHeader/scroll-position memory across restarts (e.g. planner Notes' fold state) — a real, visible regression beyond just the window rect. | Accept for wave 0, call it out explicitly in CHANGELOG.md; do not build a general egui-memory replacement here (inspector fold state moves to Settings.inspector_folds in wave-2 inspector-gallery, not this PR). |
| [profile.release.package."*"] opt-level="s" can measurably slow epaint tessellation on 4K layouts. | Gate on bench_4k_preview (<=+10%) and the 1000-clip headless test (<10ms); if it regresses, first try excluding epaint/emath (`[profile.release.package.epaint] opt-level = 3`) before reverting the whole lever. |

## Deliberate simplifications (`// ponytail:`)

- markdown.rs is stateless (parse-and-paint per call, no cache) — planner notes are short enough that re-parsing every frame is free; add a hash-keyed Vec<Block> cache only if a note's body ever gets long enough to measurably matter.
- Pane::Presets temporarily loses Save-from-selection/rename/delete + non-adjustment template browsing; place/apply still work via reuse_ui + the existing templates.list/apply MCP tools, and this PR's templates.save covers the save direction. Full parity returns when wave-2 inspector-gallery builds the Gallery pane — this is the architecture's own documented interim state, not a bug.
- Font fallback ends at fontdb's first system face, not a curated list — fine since segoeui.ttf/consola.ttf ship on every supported Windows 10/11 SKU; only tighten if a real bug report proves otherwise.
- Main-crate opt-level "s" is one reversible Cargo.toml line, applied last, behind the perf gates. If it must stay at 3, the documented (unscheduled) upgrade path is a future se-engine workspace-member split (compose/mixer/gpu/shaders at -O3, the rest at -Os) — do not attempt that split in this PR.
- winpos's window-rect save is still a bespoke 500ms debounce (not a generic settings-autosave helper), but it now RETURNS its wake time instead of calling request_repaint_after itself, so the one NEW place that schedules a repaint is App::animate_until (via whatsnew::tick).
- notes.md is docs-refresh's (wave 3) exclusive file per the skeleton's own ownership table and is not in the .gitattributes merge=union list; this PR intentionally does not append to it. The measured size numbers this PR produces go into CHANGELOG.md (already union-merged) and goals.md instead; docs-refresh consolidates into notes.md at wave 3.
- Audit correction: the codebase carries 17 pre-existing raw `ctx.request_repaint_after(...)` calls today (app.rs x12, planner.rs x1, preview.rs x2, subtitles_ui.rs x2) and this PR does NOT migrate any of them — most live in files exclusively owned by other, later-wave workstreams (preview.rs by canvas-handles-monitor/pro-monitor, subtitles_ui.rs by transcript-captions), so a blanket migration here would breach the registry protocol's file-ownership rule for a same-behavior refactor that isn't this workstream's job. `App::animate_until` is therefore accurately scoped as 'the sanctioned path for new timed-repaint code from wave 0 onward,' not yet a codebase-wide invariant; a dedicated `chore/migrate-repaint-timers` sweep (touching each site's owning file, ideally paired with that file's next feature PR) is the documented, unscheduled upgrade path — do not silently claim the invariant already holds everywhere.
