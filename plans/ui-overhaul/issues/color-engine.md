# Color Engine

**Workstream:** `color-engine` · **Issue:** [#24](https://github.com/KashTheKing/simple-editor/issues/24) · **Wave:** 1 · **Branch/worktree:** `feat/color-engine` → `../simple-editor-wt/color-engine` · **Depends on:** size-diet, registries-schema-hooks (wave 0b: Asset.effects field, ToolDef/ACT_HANDLERS registries, ToolKind, run_tool_undoable) · **~1265 new lines · Δ exe ≈ +96 KB**

Read [agents.md](../../../agents.md), [goals.md](../../../goals.md), [notes.md](../../../notes.md) and the master plan [README.md](../README.md) (registry protocol, keymap, modifier table) before starting.

## Summary

Engine-only colour toolset: 4 new EffectKind variants (Primaries, Qualifier, Lut, FrameBlend) each with a GLSL body + CPU fallback (or gpu_only, with FrameBlend correctly wired into needs_motion() so it gets real prev/next samples), a std .cube LUT parser/cache with GPU TEXTURE_3D + CPU trilinear paths, on-demand downsampled frame_stats (histogram/percentile/mean/sample, memoized per playhead time, wired into the live-preview render path only — never export), builtin Looks (12 EffectPresets + intensity, first/sole declaration in presets.rs) reusing the existing preset-apply machinery, auto-colour/colour-match writing editable Levels/Curves, and a master/source-clip effects_for() helper (sole owner crate-wide) prepending Asset.effects at render time across all 4 compose.rs call sites plus gpu.rs. No new panes, no UI files — inspector-gallery (wave 2) and pro-monitor (wave 3) build the wheels/curves/scopes surfaces on top of this, reusing these exact fns/tool names rather than re-declaring them. Ten MCP tools cover every capability, each documented as the crate-wide canonical registration for its name; 3 unbound Actions (AutoColor, ColorMatch, BypassGrade) get real ACT_HANDLERS bodies.

## Motivation

Closes gap_matrix rows 80-84 (Looks/LUT/Primaries/Qualifier/AutoColor) and 92 (frame blending) plus architecture hooks 13 (frame readback statistics) and 14 (preset catalogue data half); serves goals.md's zero-new-deps + size-down constraints by reusing existing GLSL/shader/preset/effect infrastructure instead of new subsystems. Fixes critique 7 (master/source-clip effects) via the effects_for() prepend, verified to reuse the existing full-cache-clear check at playback.rs's asset-diff line rather than adding new invalidation logic. As the earliest-landing (wave 1) owner of colour capability, this workstream's tool names/fn signatures are now explicitly documented as canonical so wave-2/3 consumers (inspector-gallery, source-monitor) build UI atop them instead of re-declaring duplicate MCP tools or presets.rs functions.

## In scope

- EffectKind::{Primaries,Qualifier,Lut,FrameBlend}: GLSL body + ParamSpec + CPU fallback (Primaries/Qualifier/Lut) or gpu_only (FrameBlend), with FrameBlend also added to needs_motion() so its prev/next samples actually flow
- .cube LUT parser + trilinear CPU sampler + TEXTURE_3D GPU upload, both keyed by Effect.lut path
- frame_stats: downsampled (256x144) GPU readback wired into render_preview_texture (the live-preview path), memoized per playhead time, never during export/render_frame; pure CPU histogram/percentile/mean/sample compute
- builtin_looks() (12 EffectPresets) + apply_look() with an intensity master — sole/first declaration in presets.rs, reusing the existing EffectPreset/apply_effects machinery
- auto_color/match_curves: histogram-derived, editable Levels/Curves/Color effect writers
- Master/source-clip effects: effects_for() prepending Asset.effects ahead of clip.effects at render time, threaded through all 4 compose.rs apply_effects() call sites and gpu.rs's run_chain/eval_graph_on/draw_clip
- 10 MCP tools covering every capability above (kind read/mutate), canonical/sole-registration for clip.add_lut, color.auto, color.match, looks.list, looks.apply — 3 unbound Action rows (AutoColor/ColorMatch/BypassGrade) with working ACT_HANDLERS bodies
- Settings.lut_dirs (browsable LUT folders, consumed by a later UI workstream)

- src/model/effect.rs (currently model.rs:654-1140, moved by wave-0a split-god-files): EffectKind gains Primaries, Qualifier, Lut, FrameBlend (inserted before Shader in ALL, ALL: [EffectKind;25] -> [EffectKind;29]); category() gains a new "Color" bucket for Primaries/Qualifier/Lut, FrameBlend joins "Stylize" beside MotionBlur; applies_to_audio() adds all 4 to the existing all-false arm (model.rs:741-746 today); params() gains 4 arms -> P_PRIMARIES/P_QUALIFIER/P_LUT/P_FRAME_BLEND const tables; name() gains 4 display strings; needs_motion() (model.rs:829-831, currently `self == EffectKind::MotionBlur`) becomes `matches!(self, EffectKind::MotionBlur \| EffectKind::FrameBlend)` so FrameBlend actually receives prev/next motion samples through gpu.rs's run_effect/run_chain/eval_graph_on gates and playback.rs's motion-decode gate — all three key off this one predicate and none is an exhaustive match, so they silently stay MotionBlur-only without this line.

## Risks

| Risk | Mitigation |
|---|---|
| PARAM_NAMES is a hard 12-slot cap (gpu.rs:1466) shared by every EffectKind; Primaries' natural 12 knobs (lift/gamma/gain/offset x RGB + temp/tint = 14) overflow it. | Drop per-channel Offset (redundant with Lift) -> 9 (lift/gamma/gain x RGB) + temp + tint = 11, fits with 1 slot to spare; documented as a ponytail note, not a silent shortfall. |
| Any param index >= 8 needs the shader body to self-declare `uniform float pN;` (CURVES already does this at shaders.rs:777-780) or PRELUDE's p0-p7 leaves p8-p10 undefined -> link error. | PRIMARIES body declares p8/p9/p10 itself, mirroring CURVES; extra_uniforms_are_documented test extended with the new row so a missing declare fails CI, not a runtime GLSL log. |
| glReadPixels for frame_stats can stall the GL pipeline if called every frame regardless of demand. | Gated behind GpuRenderer.stats_wanted (default false, nobody sets it yet this wave) and memoized by playhead time; wired only inside render_preview_texture, never render_frame (export/thumbnails), so export speed is provably unaffected. |
| TEXTURE_3D may be unavailable on old/ANGLE GL contexts eframe's glow backend runs on. | lut texture creation wrapped like other GL calls with the existing guarded() pattern; on failure, Lut effect silently uses the CPU trilinear path in effects.rs (same graceful-degrade policy as gpu_only kinds without a program). |
| effects_for() threading project into run_chain/eval_graph_on touches call sites inside gpu.rs's hot per-clip render loop (draw_clip, called every layer every frame). | project is already a parameter one frame up (draw_clip) — no new lookup cost, no allocation on the common empty-Asset.effects path (Cow::Borrowed). |
| Asset.effects being empty by default means effects_for() must not allocate/clone when there is nothing to prepend, or every clip render regresses. | Cow::Borrowed(&clip.effects) short-circuits before any Vec allocation when asset_fx.is_empty(); pinned by an effects_for_borrows_when_asset_has_no_effects test. |
| needs_motion() gates three separate call sites (gpu.rs run_effect, run_chain/eval_graph_on, playback.rs's motion-sample decode) via a plain `==`/`matches!` check rather than an exhaustive match, so a future EffectKind that also wants motion neighbours could silently be forgotten the same way FrameBlend almost was. | Out of scope to refactor into an exhaustive match this wave (touches playback.rs's decode path, a shared file); documented here so the next motion-consuming EffectKind's author checks this predicate explicitly. |
| Multiple concurrent workstreams could independently add MCP tools/presets.rs fns covering the same colour/LUT/looks capability without cross-checking each other's landed diffs, producing duplicate ToolDef names (tool_names_unique_and_namespaced build failure) or duplicate fn definitions (compile error) in presets.rs. | This plan now names its 5 canonical tool rows and 2 presets.rs fns explicitly as sole-owner/first-declaration in files[], mcp_tools[], new_types_and_fns[], and ponytail_notes[], so later-wave plan authors (inspector-gallery, source-monitor, pro-monitor) check this document before writing their own diffs against TOOL_TABLES or presets.rs. |

## Deliberate simplifications (`// ponytail:`)

- clip.bypass toggles existing Effect.enabled on grade-category effects instead of adding a global non-destructive preview-bypass flag/render path — reuses a field that already exists; upgrade path: pro-monitor's row 64 wipe/compare window can add a separate App-side preview-only bypass later without touching this.
- LUT cache has no mtime invalidation (path-keyed only) — re-run clip.add_lut to pick up an edited .cube; add (path,mtime) keying if hot-editing LUTs is ever reported.
- apply_look() replaces the whole effect stack (same semantic as existing template apply) rather than appending — a beginner who already added a manual effect loses it when clicking a Look; upgrade path: an append-only variant if that's complained about.
- color.auto/color.match sample ONE frame_stats snapshot (at the playhead, via the live preview render path) rather than re-rendering each selected clip at its own start time — good enough for the common one-clip-at-a-time case; upgrade path: loop render.frame per clip.start when asked for.
- color_match's 'reference clip' = last id in the selection list (arbitrary but deterministic) since selection has no order today; documented in the tool's desc string.
- Primaries needs 11 of the 12 PARAM_NAMES slots (drops a separate per-channel Offset that lift/gain already cover) to fit gpu.rs's fixed p0..p11 uniform budget — do not add a 4th RGB triple without first extending PARAM_NAMES (a shared, must-coordinate change, out of this workstream's scope).
- frame_stats lives only on the live preview path (render_preview_texture); an MCP caller invoking frame.stats/color.auto/color.match while the app has no preview pane open (headless --selftest step aside) gets stats from whatever the preview last rendered, not a fresh on-demand render — acceptable for an interactive editor; upgrade path: a dedicated off-screen render_frame + compute_stats call for headless/MCP-only stats requests if that's ever needed.
- Tool/fn ownership is explicit and one-directional this wave: color-engine declares clip.add_lut/color.auto/color.match/looks.list/looks.apply and presets::builtin_looks/apply_look first; every later-landing workstream (inspector-gallery wave 2, source-monitor wave 2, pro-monitor wave 3) that needs this capability must call these exact names rather than adding parallel ones — documented here so cross-wave plan authors check this file before writing a diff against presets.rs or TOOL_TABLES.
